# 地基监视雷达阵列重构后端

Python 3.11 + FastAPI + NumPy 实现；数值优化只依赖 NumPy，不调用 CVXOPT、SciPy 或其他优化求解器。健康事件、作业和加权版本持久化到 Redis 7（AOF + RDB）。

## 组成

- `app/models.py`：Pydantic 数据契约与输入校验。
- `app/array.py`：阵列、阵因子、方向图、主瓣/第一零点/最高副瓣指标。
- `app/health.py`：去重、乱序事件归位及任意时刻状态推导。
- `app/reconstruction.py`：自定义投影 Adam + 罚函数延续的模板重构。
- `app/scheduler.py`：异步作业、进度、取消、新事件作废旧作业。
- `app/service.py`：方向图评估、方案指标、版本对比、合规检查。
- `app/storage.py`：Redis 仓储；测试默认使用进程内兼容实现。
- `app/engine.py`：在线编排、事件触发自动重构、确定性回放。
- `app/api.py`：REST 接口。

## 求解方法

约束为：

- 模板角度上 `|w^H a(θ)| ≤ L(θ)`；
- 指向方向上 `Re(w^H a0) ≥ Gmin`；
- 完好通道 `|wi| ≤ |w_nom,i|`；
- 失效通道 `wi = 0`。

这些集合分别是圆盘、半空间和圆盘/零点，问题整体凸。实现使用可微的精确罚函数和 Adam 更新，每步后投影到通道幅度约束。罚因子从 0 开始延续到有限值；初始罚 0 会先投影起点，使宽松模板立即停止，严格模板则继续收紧。设置 `max_iterations` 和 `convergence_tolerance`。达到上限仍不合规时，返回当前最佳加权、最严重违反角和超出 dB，不无限迭代。

失效通道投影直接置零，因此每个可行解和“最佳但不可行”解中失效加权都严格为零。

自动重构默认从当前生效方案热启动：通常只需少量迭代，方案变化也小；冷启动使用等幅加线性指向相位，更独立但变化较大。两种起点都作为作业参数暴露，测试均验证满足同一模板。

## 8 单元失效算例

8 单元、半波长间距、等幅同相时：

- 第一零点：约 14.48°；
- 最高副瓣：约 −12.80 dB；
- 半功率宽度：约 12.80°。

第 4 单元失效后最高副瓣约 −8.17 dB。测试模板为：

- `[-90°, -15°] ≤ -8 dB`；
- `[ 15°,  90°] ≤ -8 dB`；
- 允许主瓣增益损失 3 dB。

该模板由实际失效后的非重构方向图违反；自定义重构在两种起点下均满足，实际结果约为 −9.33 dB、主瓣损失约 −1.16 dB，第 4 单元严格为 0。

## 运行

```bash
docker compose up --build
# 文档
open http://localhost:8000/docs
```

无 Docker Redis 时，测试和直接启动使用内存仓储；生产应始终设置：

```bash
REDIS_URL=redis://redis:6379/0
uvicorn app.api:app --host 0.0.0.0 --port 8000
```

## 主要接口

| 方法/路径 | 用途 |
| --- | --- |
| `PUT /array` | 定义单元数、间距、复加权和期望指向 |
| `POST /events` | 提交一批健康事件；重复 ID 幂等，按事件时间归位 |
| `GET /events` | 查看事件 |
| `GET /state?timestamp=` | 推导任意时刻通道状态 |
| `GET /pattern?timestamp=&step_deg=` | 实际方向图与指标 |
| `POST /pattern` | 用指定加权计算方向图 |
| `POST /reconstruction-jobs` | 提交重构作业，可指定冷/热启动 |
| `GET /reconstruction-jobs` / `.../{id}` | 作业列表、进度、迭代结果 |
| `POST /reconstruction-jobs/{id}/cancel` | 取消作业 |
| `GET /weight-versions` / `.../{id}` | 方案版本及当前生效版本 |
| `POST /weight-versions/compare` | 两个版本的副瓣、主瓣损失、逐单元变化 |
| `POST /replay` | 按原始输入顺序确定性回放 |

拒收规则由模型和接口统一处理：单元数 `<2`、间距非正、幅度为负/非有限、事件单元越界、模板区间超出 `[-90,90]` 或重叠、允许主瓣损失为负。

## 一致性与作业生命周期

- 事件按 `(timestamp, arrival order, event_id)` 排序；重复事件只第一次生效。
- 版本绑定当时全部有效事件 ID、状态时刻和模板。
- 新事件到达时，若旧方案在最新状态下不满足模板，未完成的手动/自动作业全部标记 `superseded`，并以最新状态自动发起热启动作业。
- 回放会按输入到达顺序重放阵列定义、事件批和手动作业；自动作业由相同状态迁移重新生成，因此逐时刻状态和最终方案与在线结果一致（数值计算固定使用 NumPy 默认确定性算子）。
- Redis AOF 持久化；重启后恢复阵列、事件、版本、作业，中断中的作业重新排队。
